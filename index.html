运营小结

我的账号

新增子账号

这是本站唯一的账号来源：自助注册已关闭，外人无法自行注册。给店员各开一个账号，入库、出库、拍照都会记下操作人。操作员可办日常业务；只读访客只能查件和看台账。人走了直接「停用」，别删，历史流水里的操作人还能对上。

账号列表

换设备怎么办：账号只存在本机浏览器，不会自动上传。用「JSON 全量备份」导出，或开启 GitHub 私有仓库同步，账号库会随台账一起写进备份文件；新设备打开后点登录页的「导入备份恢复」即可用同一套账号登录。备份文件里是加盐哈希而非明文密码，但仍请当作敏感文件保存，别放进公开仓库。

图片存储 · 云盘

推荐 GitHub 仓库直存：照片直接提交进项目仓库的 photos/ 目录，不用云盘、不用 Worker、不用额外账号，一次配好 token 就完事。出库凭证归档到 photos/出库凭证/年-月/，入库照片放到 photos/入库照片/年-月/。仓库必须是私有——面单上有收件人手机号和地址，公开仓库会被直接拦住。也可以用云盘 WebDAV（坚果云 / 123 云盘，需 deploy/webdav-proxy.js 中转补 CORS）或本机同步目录。凭据只填在这里，绝不写进公开仓库。

缓存状态读取中…

token 复用上方「GitHub 同步」里的 Personal Access Token（Contents 读写即可），不需要再填一份。照片会按 入库照片/出库凭证 + 年-月 提交到 photos/ 下，每张照片一次 commit；仓库有 1GB 软上限，单张压缩后约 150–250KB， 自己按件量估一下。加速地址不是必需项：填了之后读图走 Cloudflare 边缘缓存、token 也可以只留在 Worker 里； 不填就直连 api.github.com，配合本机缓存也够用（详见 README 的性能一节）。

使用说明与部署

查件（最常用）

顾客报取件码、手机号后四位或扫面单，在「查件」页输入即可看到货架位、在库天数，若已取走则显示取件人与出库时间；在库件可一键跳到「取件出库」并自动勾选。工作台顶部也有快速查件框。

取件码 = 货号

入库自动生成取件码，默认由货架位压缩而成（A-01-2 → A012），顾客报码就能定位货位；也可在入库框里手改，或在台账「修改」里改。入库成功后点「打印标签」用普通打印机打小票贴面单，不需要专用打印控件。规则可在「驿站设置」里改成每日流水号或关闭；改规则只影响新入库的件，旧记录保持原码。

合并出库

同一顾客的多件包裹一起勾选出库即自动合并为一个批次：共用同一张取件凭证（每件记录里都能翻到）、流水只记一条。误操作可在「操作流水」点「整批撤销」一次性把整批恢复在库；若某个货位已被新件占用，会整批拒绝并提示，避免只撤一半。批次号也能直接粘进查件框查同批所有件。

日常流程

入库登记（生成取件码、可拍面单照）→ 包裹按货架位上架 → 顾客报码或尾号检索 → 拍照留证后确认出库（多件自动合并出库）。所有动作写入操作流水，误操作可撤销出库。

摄像头与拍照

「打开摄像头 / 拍取件凭证」会直接调用设备摄像头，可连拍、切换前后镜头；拍照后自动压缩并写入云盘。摄像头需要 https 页面（GitHub Pages 满足）并授权相机权限，用本地 file:// 打开或浏览器不支持时会自动回退到系统相机 / 相册。出库默认要求先拍照，可在「图片存储」里关闭。

账号与权限

首次打开注册站长账号，之后在「账号管理」里给店员开子账号。站长可改设置、导入备份、管账号；操作员可入库出库与改台账；只读访客只能查件和看板。每条流水都记录操作人，可在流水页按姓名搜索。账号随 JSON 全量备份 / GitHub 同步迁移，换设备打开后点登录页「导入备份恢复」即可。

数据在哪

台账与账号都保存在浏览器 localStorage，无需服务器。开启 GitHub 同步后，台账与账号库会一起写入指定仓库的 JSON 文件；仓库必须是私有，里面含账号密码哈希与收件人后四位。Pages 站点本身不要放任何令牌。

GitHub Pages

把本仓库推送到 GitHub 后，在 Settings → Pages 选择分支 main、目录 /（root）即可获得在线地址。纯静态，无构建步骤。

照片存进 GitHub 仓库（默认）

最省事的一条路：照片直接提交进项目仓库的 photos/ 目录，不用云盘、不用 Worker、不用第二个账号。配置只要两处：先在下方「GitHub 同步」填 Personal Access Token（Contents 读写即可）和 owner/repo，再在「图片存储」把写入方式选 GitHub，点「用同步里的仓库」+「测试连接」。照片按 photos/入库照片/年-月/（RK- 前缀）与 photos/出库凭证/年-月/（CK- 前缀）提交，每张照片一次 commit。仓库必须是私有：面单上有收件人手机号与地址，公开仓库默认被拦下，要写公开仓库得手动勾「允许写入公开仓库」。仓库有 1GB 软上限，单张压缩后约 150–250KB，按一天 100 件算约每月 600MB，件量大就把「图片最长边」降到 1200 或定期清理旧月份目录。

照片存云盘：坚果云

免费版就含 WebDAV，不用会员。网页版 → 账户信息 → 安全选项 → 第三方应用管理 → 添加应用密码（只显示一次）；入库照片写入 express-station/入库照片/年-月/（RK- 前缀），出库凭证写入 express-station/出库凭证/年-月/（CK- 前缀），文件名带拍摄时间。坚果云不返回 CORS 头，直连 dav.jianguoyun.com 会被浏览器拦，所以要把 deploy/webdav-proxy.js 部署成 Cloudflare Worker，把 Worker 根地址填进「CORS 代理地址」，上游保持默认 https://dav.jianguoyun.com/dav；账号填注册邮箱，密码填应用密码。免费版每月上传 1GB / 下载 3GB，照片量大就把「图片最长边」设为 1200。

照片存云盘：123 云盘（需账号仍保留 WebDAV 权益）

123 自 2026-11-04 起，新注册账号与新开通会员都不再含 WebDAV，只有老账号、或会员权益连续有效的老会员才看得到入口。有入口就走：网页版 → 工具中心 → 第三方挂载 → WebDAV 授权管理 → 添加应用（权限勾「读写」）→ 复制应用密码。Worker 路由 /pan123，上游保持默认 https://webdav.123pan.cn/webdav，账号填手机号/邮箱；若后台给的是专属域名，在 Worker 里设环境变量 UPSTREAM_PAN123 覆盖。看不到这个入口就别耗时间，直接选坚果云。

照片存云盘：自定义 / AList

用 deploy/docker-compose.yml 在 NAS 上启动 AList 挂其它网盘，开启 WebDAV 后把 https://你的域名/dav 填进上游地址。AList 自带 CORS 头，可以直连、不必填代理；但必须是 https，内网 http 地址会被 Pages 拦截，可用 Cloudflare Tunnel / Nginx 反代。Worker 的 /webdav 路由配合环境变量 UPSTREAM_CUSTOM 也能代理无 CORS 的自建服务。

安全提醒

手机号只保留后四位。云盘应用密码只存在本机浏览器、随请求头透传给自己的 Worker，Worker 代码里不写任何账号密码；第三方网盘 token 只填 AList 后台。本机 deploy/.env 与 deploy/data/ 已被 .gitignore 排除，绝不提交到公开仓库。建议在 Worker 里配置 ALLOWED_ORIGINS / PROXY_KEY，避免地址泄露后被他人借用额度。
